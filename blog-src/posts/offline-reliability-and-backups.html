Ten minutes before the service the router drops, and the song you meant to find online will not load. Or the laptop will not boot at all, and the only copy of your themes and custom songs is on its disk. These are ordinary Sunday problems, and they are much less frightening if you decided in advance what happens when they occur.

This post is about designing the media desk so it does not depend on things you cannot control: the internet, a single computer, or one person's memory. None of it needs a big budget.

List what can fail

Start with a plain list. For each thing, write what you would do if it vanished at 9:55 on a Sunday.

What failsLikely causeWhat you need ready
InternetRouter, provider outage, shared Wi-Fi overloadedEverything for the service stored on the computer
Wi-Fi inside the buildingAccess point, too many phonesA wired connection or an alternative for any phone or tablet control
The laptopUpdate, hardware fault, drink spilledA spare machine with the same software and a recent backup
The projector or cableLamp, loose plugA spare cable; a TV as a fallback
The one person who knows howIllness, travelA written checklist and at least one trained backup
The filesDisk failure, accidental deletionA dated backup on a separate drive

The point is not to be paranoid. It is to know, ahead of time, which of these you have already handled and which you are leaving to luck.

Design for offline from the start

The simplest reliability rule is that the live service should never need the internet. That means everything you will show on Sunday is already on the machine by Saturday night.

  • Songs and lyrics in a local library, not fetched on the day.
  • Bible text installed locally, not read from a website.
  • Presentations saved to the computer, not opened from a cloud link.
  • Videos and backgrounds copied to the local media folder. Streaming a clip from the internet during a service is a bet.
  • Fonts installed or loaded into the software, so a missing font does not change the look of your slides.
  • Software updates done during the week, not on Sunday morning. Never let a laptop decide to restart for an update during a service.

Treat internet-dependent extras as optional. Live streaming, a song search, or a cloud-based speech tool are useful when they work, but the service should still run if they do not.

What Vifug does offline

Vifug is designed this way. According to its documentation, everything needed to run a service works without internet. The song library of 325 songs and the offline Bible are already installed, and the desktop app is offline-first by design. The things that use the internet are optional: live streaming, Deepgram speech recognition (an on-device engine works offline), song search, phone camera pairing and update checks. Live streaming, recording, NDI and library import need the desktop app.

Two practical notes follow from that. First, if your church's line is unreliable, run the desktop app rather than the browser version. The guide says a hosted deployment needs a connection, and suggests using the hosted one for rehearsal and planning only. Second, the phone remote and stage display travel over your local network, not over the internet, so they depend on the building's Wi-Fi rather than on the outside world. Both devices have to be on the same Wi-Fi, which is described in the remote chapter. If the Wi-Fi itself is the weak point, test the remote before the service and keep a plan that works from the desk alone.

Back up on a schedule

A backup is a copy you can actually restore, kept somewhere other than the computer it came from. Three rules cover most of it:

  1. Keep more than one copy. One on the computer is not a backup. One on a USB stick or external drive is. One more in a synced folder or at a team member's home is better.
  2. Do it on a schedule. After every significant change, and at least weekly. Tie it to something you already do, like the Monday review.
  3. Test a restore. A backup you have never restored is a hope, not a plan. Do a restore on a spare machine at least once.

Label drives with the date. If you rotate between two sticks, you always have the previous one if the latest turns out to be damaged.

Backing up in Vifug

In the desktop app, backup, restore and import all live in Settings, then General, then Backup. The back up, restore and move chapter describes three buttons:

  • Back up now copies the whole library and your media files into a dated folder. Pick a USB stick, an external drive or a synced folder, and Vifug creates a folder named Vifug-Backup followed by the date and time. Inside are a file called vifug.db, which holds every song, presentation, theme, font, plan and setting, and a Media folder with pictures, videos and sound. Keep the two together.
  • Import from another Vifug adds another library to this one. Nothing already there is changed or replaced, and nothing is added twice. Importing the same folder again adds nothing, so it is safe to repeat.
  • Restore from backup replaces this library with the backup's. It asks you to confirm, adds the backup's media beside what is there, and restarts the app. Anything added since that backup was made is lost, so back up first if you are unsure.

The guide recommends backing up before anything risky and regularly. A good habit is to press Back up now at the end of each week's final rehearsal and again after a big change such as importing songs or building new themes.

There is no Backup group in the browser version, since a browser cannot read folders on your computer. This is another reason to run the desktop app for the main service machine.

Keep a spare machine

A second computer that can run the service is the best single reliability investment you can make. It does not need to be new or fast. An older laptop that can drive a projector is enough.

  • Install the same software and keep it updated.
  • Copy your latest backup onto it and restore or import it.
  • Keep it charged and stored with its own power lead and a spare video cable.
  • Test it once a month: plug it in, project a song, check the stage display and remote.
  • Keep a spare video adapter with it, since the adapter is often what goes missing.

Moving to the spare in an emergency is then a matter of connecting the cable and loading the plan. Note what is not carried across when you import: according to the guide, settings, service plans and live history are not imported, since they describe the other computer's services. So if you need the same plan, rebuild it or use Restore, which brings settings and plans with it, and keep a printed run sheet as a safety net.

Restoring calmly

If the main machine dies, work through this in order:

  1. Switch to the spare laptop. Connect the projector.
  2. Plug in the backup drive and open Settings, then General, then Backup.
  3. For an identical copy, choose Restore from backup and pick the Vifug-Backup folder itself. For a spare that already has its own settings, choose Import from another Vifug to add the songs, media and themes.
  4. Check the first few songs and the first presentation on screen.
  5. Carry on the service from the printed run sheet.

If Vifug says there is no vifug.db, you probably picked the USB stick or the Media folder rather than the Vifug-Backup folder. If a picture shows as missing, the backup was likely copied without its Media folder. Copy the whole folder and try again.

A simple weekly routine

  • Monday: Back up now, to a labelled drive. Put the drive in a different place from the laptop.
  • Midweek: install updates on both machines and restart them.
  • Saturday: check the spare still boots, load the plan on both if you can, and make sure every video and picture is local.
  • Sunday: arrive early, and run the pre-service checklist.

Where to start
